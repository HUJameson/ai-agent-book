# search-codegen WebUI 需求规格

版本：v0.2 · 2026-11-01 · SSE 扩展已确认、已实现（离线验证）；v0.1 已实现

## 1. 目标与参照

为 chapter1/search-codegen（实验 1-3：搜索与代码计算）提供本地中文 WebUI，沿用 context/webui 的暗色玻璃拟态、历史侧栏、后台任务和实发请求展示。用户可以在页面选择后端、提交任务、接着回答澄清问题，并核查搜索和代码执行的真实证据。

v0.1 基线已实现；v0.2 SSE 已按确认方案实现，验证结果见 VALIDATION.md。与目录上一层的 SPEC.md（已实施的后端选择修复）分别维护，不覆盖原文档。

## 2. 范围与默认选择（v0.2 更新）

| 决策 | 当前方案 |
|---|---|
| 用户与部署 | 本地单用户，默认仅监听 127.0.0.1 |
| 视觉 | 对齐 context 的近黑蓝底、玻璃卡片、靛蓝/青色渐变、折叠详情和历史侧栏 |
| 功能 | 任务对话、多轮续接、离线请求预览、实验验证、导出和历史 |
| 后端 | openai / dashscope / openrouter，沿用 Config.resolve，不自动兜底 |
| 执行 | 所有联网任务后台运行，前端通过 SSE 订阅增量；状态查询作为恢复/降级兜底；全局同时只运行一个任务，忙时返回 409 |
| 技术方向 | FastAPI + 原生 HTML/CSS/JS，独立 webui/requirements.txt，零前端构建 |
| 历史 | 服务端内存，最多 50 个已结束记录；刷新可回看，重启不恢复 |
| 默认端口 | 8001，可通过 --port 修改，便于与 context 的 8000 并行使用 |

首版不包含：公网部署、鉴权、多用户、数据库、网页填写密钥、本地执行模型代码、文件上传、自动重试、可靠取消、任意任务正确性自动评判、完整手动测试集 GUI。本次增加基于真实供应商事件的增量输出，不要求每个 Token 独立刷新，也不保证首个事件到达时间。不得用虚构事件或进度百分比代替真实执行状态。

## 3. 页面与操作流程

左侧为新建会话、历史和任务状态；主区分为“任务对话”“请求预览”“实验验证”三个页签；设置面板展示后端、模型与参数。宽屏使用双栏，窄屏可折叠侧栏，JSON 和长代码在卡片内滚动。

### F1 后端与参数

- 后端选项显示名称、默认模型、密钥是否已配置、实际 Base URL；明确“已配置”不代表鉴权验证成功。
- 默认值取服务端 Config，支持覆盖模型。百炼共享域名与业务空间专属域名均须显式传 backend=dashscope，不能依赖域名推断。
- Base URL 由服务端 .env/环境变量管理，页面只读；修改后提示重启服务加载。不得返回完整或部分 API Key、Authorization 等认证头。
- 提供“使用工具”开关（开启时沿用 web_search + code_interpreter，不引入单独禁用某一个工具的新语义）。
- OpenAI/OpenRouter 显示 reasoning、verbosity 控件，默认值与 CLI 一致；百炼禁用并说明这些控件不发送，由后端原生处理思考。不保证每个模型支持全部枚举值；服务端错误须原样保留可排查信息并脱敏。
- max_output_tokens 为可选正整数，未填写使用服务端默认值；不展示无效的 temperature 调节。
- 后端、模型和执行参数在会话创建后固定。需要调整时新建会话，避免 previous_response_id 被跨模型或跨后端误用。

### F2 任务对话与多轮澄清

- 多行输入，Ctrl/⌘+Enter 提交；提供首都距离、比特币趋势分析、基础连通性三个可编辑示例。首都示例明确为教材选定的十国数据集，不宣称是实时成员名单。
- 首轮创建独立 Agent；同一会话后续轮次复用 Agent，通过 previous_response_id 续接。只展示“模型回复”，不因出现问号就断定模型完成了规范澄清。
- 新建会话清空上下文关联。执行失败保留失败轮及证据，不自动重发；重试由用户主动提交，不承诺避免重复计费。
- 单次失败不覆盖上一轮成功的 response_id。页面只在上一任务结束后允许同会话下一次提交。
- 流式过程中以安全纯文本展示正文并标记“生成中”；结束后用完整最终响应替换预览并渲染 Markdown，表格、代码块与链接可用。HTML 原文不执行，外链限制为 http/https。

### F3 长任务反馈

- 点击执行后立即返回 job_id，不让浏览器 HTTP 请求等待整个模型任务结束。
- 状态为 queued / running / completed / error；展示开始时间、已用时、所选后端与模型，并显示“等待模型响应，可能需要数分钟”。queued 只用于已接受任务启动前的短暂状态，不提供排队积压。
- 通过 SSE 持续推送答案增量、真实工具状态及任务状态；首个正文增量抵达后即可显示，不等待任务终态。只有供应商发出工具事件时才显示对应阶段；上游没有事件时保留等待提示，不伪造“正在搜索/正在计算”。
- 实验验证通过同一 SSE 通道展示后端、任务阶段（首都/澄清首轮/澄清续接）、对应正文与真实工具事件；已完成后端数仍作为实验总体进度，不展示估算百分比。
- 默认订阅 SSE；断线按事件游标重连，刷新通过任务列表与当前流快照恢复。状态查询接口保留；SSE 不可用时降级为每秒状态查询，不重新提交模型请求。离开页面不代表停止计费或取消请求。
- 现有服务端超时不被浏览器 SSE/查询超时替代；失败后显示错误类型、可用的 HTTP 状态/请求 ID、脱敏详情和已用时。空正文明确显示“服务端返回空响应”，不得当作成功。

### F4 结果与执行证据

- 输入 Token 拆分展示总输入、缓存命中、非缓存输入（总输入减缓存命中）；缓存是总输入的子集，缺少缓存字段时后两项显示“未提供”，真实零命中保留 0。
- 结果包含答案、总耗时、输入/输出/思考/总 Token；缺失用“未提供”，不补造零值；不推算未确认的费用。
- 展示请求模型、返回模型、实际 provider、实际 Base URL，以及本轮调用数。
- 工具面板只根据返回的真实 tool_calls/output_items 展示类型、状态和可用的输入/输出；completed 徽章必须来自真实完成记录。只在答案里写“已搜索/已计算”不构成工具执行证据。
- 引用列表从真实 citations 提取，点击打开来源；没有则显示未提供引用，不从答案自动补成执行证据。
- 每轮“实发请求”按“工具定义 → instructions → input → 其他请求参数”展示，标明 tools 为独立字段，并显示 previous_response_id（如有）；不把它伪装成完整 messages 历史。
- 多轮续接依赖服务端上下文，页面说明“本轮只发送增量输入与响应 ID，历史展示不代表历史全文重新发送”。
- 请求 JSON、原始响应、output_items、错误与 api_turns 可折叠查看；字段缺失标明未记录。思考只展示 API 实际返回且适合展示的摘要/内容，不推测隐藏思考。
- 提供本轮 JSON、会话 JSON 和答案 Markdown 下载；保留工具证据与参数，去除认证信息。模型生成文件仅在 API 提供可访问链接时显示，不承诺未实现的容器文件下载。

### F5 离线请求预览

- 不需 Key、不调用模型，复用 Agent 的 dry_run；支持新任务和已有会话下一轮请求预览，不改变会话历史或 previous_response_id。
- 展示最终 backend、模型、URL 和真实构造请求体，百炼必须可见 stream=true 及实际工具结构。
- 预览明确标为“未执行”，不计入真实任务统计；工具开关关闭时不得显示已发送工具定义。

### F6 实验验证

- 提供“运行实验 1-3”入口，选择一个或多个后端，默认仅选当前后端；提交前明确列出将产生多次真实 API 调用，不自动执行。
- 复用 run_experiment_1_3.run_backend、validate_asean、validate_clarification、acceptance，后端顺序执行，缺 Key 预检失败，不静默跳过。
- 展示两项实验：教材十国首都距离；先澄清再续接的比特币分析。以卡片/对比表呈现每项既有检查、各后端耗时与 Token，提供 JSON 报告。
- 原样保留现有 OpenRouter 诊断路径与正式验收资格区别；请求成功和实验验收通过分别显示。
- 说明既有校验器的局限：例如“包含距离单位”不等于数值误差校验，“包含问号且无工具”是澄清启发式，不能展示为严格语义证明。不扩展现有验收算法。
- 某一后端失败也保留其错误并继续后续后端；不自动重试，不更换模型或凭据。

### F7 历史与数据生命周期

- 历史按更新时间倒序，区分对话和实验；可回看完整轮次、配置和证据。运行中的任务始终可找回，不被 FIFO 淘汰。
- 最多保留 50 个已结束记录；淘汰会话时同时释放 Agent 与响应关联。运行中会话禁止删除，清空历史也不取消任务。
- 浏览器只保留必要记录 ID，不在 localStorage 保存密钥或完整对话；进程重启后找不到旧记录时给出明确提示。

## 4. 接口需求（路径草案，具体结构由 DESIGN 固化）

| 方法与路径 | 职责 |
|---|---|
| GET /api/defaults · /api/backends · /api/samples | 默认值、后端状态及能力、示例 |
| POST /api/preview | 返回脱敏请求预览，不执行 |
| POST /api/sessions | 创建固定配置的新会话 |
| POST /api/sessions/{id}/turns | 提交一轮，立即返回 job_id |
| POST /api/experiments | 启动实验后台任务，返回 job_id |
| GET /api/jobs · /api/jobs/{id} | 恢复运行任务列表、状态及流预览快照（查询降级） |
| GET /api/jobs/{id}/events | SSE 订阅、游标重放、快照重置及终态通知；不触发模型执行 |
| GET /api/history · /api/history/{id} | 历史列表与完整详情 |
| DELETE /api/history · /api/history/{id} | 清除已结束记录，运行中记录保留并说明 |
| GET /api/exports/{id}?format=json或md | 受支持的结果下载；实验仅 JSON |

参数无效返回 422，缺 Key 返回 400，资源不存在返回 404，执行忙或会话冲突返回 409。成功接收后台执行返回 202；后续业务失败通过 job.status=error 和结构化错误表达，不让轮询请求本身伪装成 HTTP 500。未预期服务异常返回脱敏 500。

## 5. 复用边界与非功能要求

- 放在 chapter1/search-codegen/webui/，复用 Agent 与 Config，不通过子进程抓取 CLI 输出，不复制第二套工具协议或模型调用逻辑。
- 借鉴 context 的服务/runner/job manager/静态页面分层；不直接耦合 context 的业务类型和上下文消融逻辑。CLI 原调用行为保持不变；v0.2 允许在 Agent 和实验入口新增可选流参数与事件回调，具体兼容方式见 DESIGN。
- UI 的后台 job 是本地线程任务，与 Responses API 的 background 字段无关；不因后台执行而给百炼添加 background=true。
- 读状态不被长请求阻塞；Agent 可变状态按会话隔离，单轮及实验执行共用全局互斥控制。
- Markdown/原始 JSON 防 XSS；密钥仅服务端读取，导出及异常内容也须脱敏。前端依赖本地 vendor，不依赖外部 CDN；仅在需要时引入图表库。
- 内存历史有界；单条响应和详情展示的大小上限、截断/下载策略由 DESIGN 明确，截断必须提示，不能默默改变完整证据。
- 默认本地监听、同源访问；无宽泛 CORS，不从网页接收任意目标 URL 或系统命令。

## 6. 验收与测试

1. 独立依赖安装后可在 127.0.0.1:8001 启动；中文暗色页面可操作，窄屏可使用。
2. 无 Key 时能预览，但实际执行明确提示缺失的变量；配置状态与结果中都不出现密钥。
3. 离线测试验证显式 dashscope + 专属域名生成正确百炼请求；后端切换、新会话隔离与参数有效性正确。
4. 使用可控流式替身验证终态之前可见正文/真实工具状态、queued/running/completed/error、SSE 重连与刷新恢复、409 和失败不重提模型请求。
5. 两轮对话真实传递上一成功 response_id，预览不修改状态；重启/淘汰/失败场景提示准确。
6. 工具与引用展示完全来自证据；无工具、缺字段、空响应、超时均可解释。Markdown、工具描述及错误中的 HTML 不执行。
7. 实验结果与既有校验器一致，包含成功、失败、部分后端失败及 OpenRouter 资格区别。
8. 历史回看、50 条 FIFO、运行记录保护、导出及敏感信息脱敏通过测试。
9. 新增测试全部离线，无需真实 Key；现有后端选择及 Responses/配置测试不回归。真实 API 验收另行由用户发起，不在启动页面或测试时自动调用。

## 8. SSE 扩展验收细则（v0.2）

1. 覆盖单轮对话、多轮续接和实验验证；WebUI 为三种已支持 backend 显式请求流式响应。供应商是否支持选定模型/工具组合由真实响应决定，不作无依据保证。
2. 供应商不支持流式或返回错误时显示真实错误；不静默切换模型、后端或自动以非流式重发，避免重复调用和计费。旧 CLI 的默认请求模式与 dry-run 语义不变；WebUI 预览应准确反映新增的流式请求。
3. 增量文本按轮次/实验阶段和输出项隔离，不把思考片段混成最终答案。首版 SSE 扩展仅实时推送正文、工具状态和任务状态；供应商可展示的思考摘要仍在终态证据中查看，不新增隐藏思考采集或推测。
4. 工具状态展示 added/in_progress/completed/failed 等真实信号；没有 completed 证据不能因 SSE 关闭或正文结束就宣称工具完成。未返回的参数、代码或输出不得补造。
5. SSE 的连接成功、心跳、文本生成完毕与模型任务成功分别处理。只有任务终态事件或状态接口才能确定任务已结束；最终 Token（含缓存拆分）、引用与下载内容以最终结果为准，流式阶段未知用量显示“未提供”。
6. 网络重连不重复正文、不漏掉终态；回放游标过期或无效时用服务端快照覆盖当前视图。支持任务极快完成后才订阅、刷新恢复、查看其他历史后返回正在运行任务。
7. 生成后失败时保留已显示的部分答案，明确标记“未完成，仅供查看”；失败内容不得被导出成成功答案，不更新会话续接 ID。流中断且缺最终响应视为失败。
8. 订阅与模型执行解耦，浏览器离开、订阅数变化或慢客户端不取消或重新执行任务，也不占用模型执行令牌。SSE 保留有界缓冲与快照；预览被截断时须明确提示，最终完整证据仍遵循既有容量/导出规则。
9. 增量同样遵守脱敏与 XSS 防护，包含跨数据片段拼接的密钥不得泄露；只发布投影字段，不透传完整供应商事件或认证头。
10. 所有新增 SSE 测试离线，验证首个增量先于终态、中文/多行、碎片化帧、重连去重、缓冲淘汰、心跳、慢客户端、终态关闭和超时失败；真实付费调用仍需用户主动发起。
